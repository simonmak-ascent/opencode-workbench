## What I do

- Research competing products, open-source alternatives, and market solutions for a given domain
- Produce comparative analysis with feature matrices, pricing, tech stacks, and differentiation
- Identify market gaps and opportunities based on public data, documentation, and community sentiment

## When to use me

Use when: evaluating build-vs-buy decisions, researching competitors before building, or understanding the landscape of tools/libraries in a space. Trigger phrases: "analyze competitors for...", "what are the alternatives to...", "build vs buy...", "market research for...".

## Workflow

1. Clarify the product domain, target users, and key differentiators the user cares about
2. Search for known competitors (both commercial and open-source) using web search and GitHub
3. For each competitor, gather: core features, tech stack indicators, pricing model, GitHub stars/activity, community health, key strengths and weaknesses
4. Create a feature comparison matrix across 8-12 dimensions relevant to the domain
5. Analyze differentiation opportunities — what is underserved?
6. Summarize with: market map, comparison table, build-vs-buy recommendation, and recommended tech approach

## Output format

```markdown
# Competitive Analysis: [Domain]
## Market Overview
## Competitor Profiles (3-6)
## Feature Comparison Matrix
## Differentiation Opportunities
## Build vs Buy Recommendation
## Recommended Approach
```
